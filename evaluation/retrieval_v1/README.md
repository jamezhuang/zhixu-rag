# 新员工知识库检索与回答依据测试集 v1

本测试集为虚构电商代运营公司的员工入职与业务制度问答设计。语料、问题和相关文档标签均为项目作者设计，尚未经过独立标注者复核；结果仅用于当前项目的可复现实验。

## 数据组成

- 18 份逻辑文档，20 个版本：公司业务、岗位职责、入职学习、试用期授权、审批流程、经营指标等。
- 32 条单文档问题：包含直接提问和同义表达。
- 8 条跨文档问题：需要两份文档共同提供完整依据。
- 8 条日期与版本问题：覆盖旧版、新版、2026-07-01 生效边界。
- 6 条不可提供所求信息的负例：无有效日期制度、年假天数、私人电话、真实经营数据、统一折扣额度和赔偿上限。部分可依据文档解释“无统一标准”，但不能编造所求数值。

每条正例包含问题、查询日期、相关文档版本和支持原文。语料文件与 SHA-256 指纹保存在 dataset.json。原文片段用于审核标签，不输入生成或评审模型，避免标准答案泄漏。

## 公平比较

比较 BM25L、Qwen3-Embedding-0.6B + Milvus HNSW、RRF 混合检索、混合检索 + 本地 BGE-reranker-v2-m3。全部使用相同冻结语料、应用分块函数和查询日期过滤。

与应用一致，每个召回分支最多 12 条，RRF k=60，融合最多 16 条，最终返回最多 6 个片段，再按文档版本去重计算排序指标。全量指标只使用 48 条正例；负例不被赋予虚假的 Recall 分数。P@1/Recall@3/MRR@6 的评估单元是文档版本，不是答案正确性，也不是精确条款片段命中率。

跨文档问题以所有指定文档为相关集合，额外报告“完整证据覆盖@3”。标签可能没有穷举全部可替代文档，故人工复核仍然必要。当前测试不执行 LangGraph 的问题拆分、查询改写、第二跳或会话记忆，不能据此声称这些组件的收益。

## 忠实度与幻觉率

只对 hybrid_rerank 检索结果生成回答，再用独立的一次模型调用逐结论评审。生成和评审均使用当前配置的 DeepSeek 模型；评审不接触标准文档标签，只查看实际检索证据。

- 忠实度：受到证据支持的结论数 / 所有可核验结论数。
- 幻觉率：无依据或与证据矛盾的结论数 / 所有可核验结论数。
- 无法判定比例单列，因此忠实度与幻觉率不一定互为补数。
- 另报含幻觉回答比例、无可核验结论回答数、评审失败数，以及正例/负例分组结果。
- 结论必须逐字摘自回答，支持/矛盾的引用必须逐字来自实际检索正文或文档版本、有效期元数据，否则重评一次；仍失败则记为评审失败，不计作正确。
- “没有可核验结论”不会获得 100% 忠实度。拒答标记与原回答保留，拒答适当性需人工复核。
- 对单独的“无法/不能确认”等非事实声明使用固定规则排除，另存被排除的原始评审，避免评审模型将自我限定错误计为幻觉。“公司没有统一额度”等制度事实仍参与核验。

本次评审经历两次口径修正：纳入版本有效期元数据、排除单独的无法确认声明；复用同一批已生成回答，不修改检索标签或问题。初始评审保存在 data/retrieval-evaluation-initial.json，元数据版原始评审保存在 data/retrieval-evaluation-metadata-raw.json。

已发现历史权限与 FLOW-006 未版本化的导师复核要求可能出现口径冲突；R043 保留为待复核案例，不能凭推测指定制度优先级。

这些是模型辅助评估，不等同人工真值。相同型号模型的生成和评审可能存在共同偏差，数据规模也较小；不应直接作为真实企业效果或线上 SLA。

API 生成与语义评审具有随机性，重复实验可能得到不同分数；本次分数对应报告中保存的固定回答与评审记录。

## 四种检索方案的忠实度对比

执行 `python -m scripts.compare_grounding`，对已保存的 BM25L、稠密检索和 RRF 混合检索结果补充生成与评审，复用混合检索加重排的固定回答。各组均使用同一批 54 条问题、同样的生成提示词与 v1.2 评审口径，标准标签不输入模型。输出 data/grounding-comparison.json 和同名 .md。

报告同时列出结论级忠实度、幻觉率、无法判定比例、含幻觉回答比例、正例拒答、负例拒答、无事实回答数和评审失败数，并单独统计 48 条正例。检索覆盖率更高不保证忠实度更高；回答可以有依据但不完整，不能把该指标直接等同回答质量。

脚本可断点续跑，只重试未完成或失败的评审，复用此前生成的原回答，并保存失败历史；不重新生成多个回答后挑选最高分。本次为每组一次实验，结果不代表统计显著差异。

评审片段末尾标点与回答不同时，仅允许去除末尾标点后逐字定位，记录原片段及对齐方式；内部词语不同仍拒绝，支持证据的原文校验不放宽。

## 复现

在项目根目录执行（需要配置真实 Embedding / DeepSeek API，并准备本地重排模型与 Milvus）：

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_retrieval --phase all
```

结果：data/retrieval-evaluation.json 和同名 .md。原始回答、排名、证据、结论评审与人工复核栏均保留。

若只需续跑失败或未完成的回答评审：

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark_retrieval --phase answers
```

脚本使用私有内存数据库分块、唯一临时 Milvus 集合检索；结束后仅删除该临时集合，不写入现有业务数据。Embedding 缓存在 data/evaluation-cache，按模型、语料、维度与查询指纹复用。

build_retrieval_dataset 脚本用于重新生成当前 v1 快照。正式比较后若修改题目、标签或语料，应另建版本并重跑，不能把调题后的分数混作原始测试结果。
