# 分块策略对比实验

本实验使用已有的冻结新员工制度问答测试集：18份逻辑文档、20个版本、48条正例和6条负例，不修改问题或标准证据标签。

## 实验组

四种分块策略各测2200和128字符目标，共8组：

- heading：真实应用标题边界＋长度软控制，默认2200；保留整行，未新增overlap。
- fixed：等长字符硬切，overlap=0。
- recursive：段落→句子→换行→空白→字符回退，满足硬上限，overlap=0。
- semantic：相邻句Qwen向量的余弦相似度低点作为边界，阈值取语料相似度25分位数，最短合并64字符；超长语义组复用递归切分，不利用问题或标签选阈值。

2200是生产配置，128是预先指定的边界压力实验。现有正文均不足200字符，不能把本次结果外推到长文档；128组只用来检查边界影响，不是调参得到的推荐生产配置。所有策略统一使用LF换行。

## 固定条件

全部使用相同语料与日期有效性过滤、文档标题及可追踪的章节元数据、Qwen3-Embedding-0.6B、Milvus HNSW、BM25L、RRF和本地BGE-reranker-v2-m3 CPU int8。最终返回六个片段，排序指标按文档版本去重。替代方法的片段保留其覆盖章节名称，不能只有heading拥有标题信息。

不调用回答生成/忠实度评审模型，也不执行LangGraph改写、多跳和原文扩展，专门评估分块后的直接检索。Embedding和相同查询-片段的重排分数使用指纹缓存，不能把缓存时延当成算法速度收益。

## 指标

- P@1、文档Recall@3、MRR@6：沿用已有48条正例的文档版本标签。
- 原文证据@3/@6：gold原文是否在同文档正确版本的某个单片段中完整命中；不把两个残片合并算完整命中。
- 限制条款完整率：含不能/不得/必须等预设词的20条完整句子，能否保留在单片段中。这是自动检查，不替代所有业务条件的人工标注。
- 块数、平均及最大字符数、超过目标的块数。
- 前6片段证据正文的平均Token估算量：不含系统提示词、历史和元数据，不等于真实API输入量或费用。

## 复现与结果

```powershell
.\.venv\Scripts\python.exe -m scripts.compare_chunking
```

脚本复用完整报告可跳过已完成实验；Embedding、本地重排分数按完整输入指纹复用。每组仅创建自己的临时Milvus集合，结束后删除，不改变生产知识库。

- 汇总：data/chunking-ablation/report.md / report.json。
- 每组分块：data/chunking-ablation/策略-字符数-chunks.json。
- 每组逐题排名、证据及指标：同目录的策略-字符数.json。
- 策略实现：evaluation/chunking.py；真实标题分块：backend/app/knowledge.py。
- 单测：backend/tests/test_chunking_comparison.py。

当前配置下，标题方案的P@1较高、证据正文估算体积更小，但其他方案的文档Recall@3略高；不应只选择某一指标宣称全面最优。测试没有自动改变生产默认方案，也没有证明统计显著性。具体数值以汇总报告为准。

128字符压力组中，固定字符硬切的限制句完整率为90%（18/20），其余三组为100%；递归方案在该配置的原文证据@6达到100%。这说明标题分块是当前合理折中，但不能据此否定递归或语义分块。
